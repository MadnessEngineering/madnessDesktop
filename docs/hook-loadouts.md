# Hook Loadouts

Hook Loadouts install a bundle of git hook scripts into a repository, and let
you switch individual scripts on and off, from the Madness Desktop UI.

## How it's laid out

Installing a loadout creates a `.githooks/` folder in the repository and points
git at it with `git config core.hooksPath .githooks`. For each hook type the
loadout uses, there's a thin **dispatcher** script plus a `.d/` folder of the
real scripts:

```text
.githooks/
  post-commit            ← dispatcher (written by Madness Desktop)
  post-commit.d/
    mqtt-context.sh
    auto-push.sh
  pre-push
  pre-push.d/
    remote-guard.sh
```

The dispatcher runs every executable `*.sh` file in its `.d/` folder, in turn,
with the hook's arguments. That's what lets several scripts share one hook.

Because `.githooks/` lives in the working tree, it's yours to commit or ignore.

## Managing loadouts

Open **Repository Settings → Hook Loadouts**.

- **Install** a loadout from its card. Scripts land in the `.d/` folders and
  `core.hooksPath` is set. One loadout at a time: uninstall the current one
  before installing another.
- **Toggle** a script off and it's renamed to `<script>.sh.disabled`, which
  the dispatcher skips; toggling it back on renames it back.
- **Uninstall** removes only the dispatchers Madness Desktop wrote (they carry
  an `# Auto-generated by Madness Desktop` marker) and their `.d/` folders, and
  unsets `core.hooksPath` if it still points at `.githooks`.

### Editing and updating scripts

Each installed script shows its status:

- **Up to date** — the same as the built-in version.
- **Update available** — the built-in script has changed since it was
  installed, and you haven't edited your copy. **Update scripts** in the banner
  brings every such script up to date.
- **Customized** — you've edited it. Updates never overwrite it; use **Reset to
  built-in** on its row to take the latest version (you're asked first).

**View / edit** opens the script in an editor; **Save** writes it to the
repository, and it's marked Customized from then on.

A loadout installed before Madness Desktop recorded what it wrote can't tell
your edits from an old copy, so any difference shows as Update available — the
banner warns that updating replaces edits.

### Custom loadouts

With a loadout installed, switch its scripts on or off, name the combination,
and click **Save as Custom Loadout**. Custom loadouts get their own card — this
machine only, stored in the app — and can be installed in any repository or
deleted.

## Built-in loadouts

| Loadout | Scripts |
| --- | --- |
| **Mad Standard** (`mad-standard`) | `mqtt-context`, `todo-prefix`, `auto-pull`, `secret-scan`, `remote-guard` |
| **Deploy Enabled** (`deploy-enabled`) | Mad Standard + `auto-push` |
| **Desktop Dev** (`desktop-dev`) | Deploy Enabled + `build-dev` |
| **Minimal** (`minimal`) | `secret-scan`, `auto-pull`, `remote-guard` |

## Scripts

### `mqtt-context` — post-commit

Publishes the new commit (SHA, branch, subject, time) and the active todo to
two MQTT topics with `mosquitto_pub`:

- `status/<device>/claude/git/context` (override with
  `MADNESS_GIT_CONTEXT_TOPIC`)
- `status/<device>/claude/git/events` (override with `MADNESS_GIT_EVENT_TOPIC`)

The broker is `MADNESS_MQTT_HOST` (default `localhost`); `<device>` is `$DeNa`
(default `macbook`). The active todo comes from
`.git/claude-session-context.json` if present.

### `todo-prefix` — prepare-commit-msg

Prefixes your commit subject with the active todo's ID, unless it already
starts with it. It reads the ID from `.git/claude-session-context.json`, or —
failing that — from the retained message on the MQTT context topic above.
Skipped for merge, squash, and amend (`commit`) messages.

### `auto-pull` — post-checkout

When you switch to `main` or `master`, runs `git pull --ff-only`. If the pull
can't fast-forward it says so and carries on. Other branches are left alone.

### `secret-scan` — pre-commit

Blocks the commit if a staged file contains an SSH public key line or an RSA,
EC, or OpenSSH private-key block. It doesn't look for API tokens or `.env`
values.

### `remote-guard` — pre-push

Enforces the branch → remote locks you set in the remotes manager (stored as
`branch.<name>.madnessRemotes` in the repo's git config): a branch locked to
`none` can't be pushed, one locked to named remotes can only go to those. A
push that includes any blocked branch is refused whole.

### `auto-push` — post-commit

Runs `git push --all` after every commit — **every** local branch, not just
the current one. Failures are reported and ignored.

### `build-dev` — post-commit

Starts `yarn build:dev` in the background from the repository root. Meant for
working on Madness Desktop itself.

## Requirements

- `bash` and `python3` for most scripts.
- `mosquitto-clients` (`mosquitto_pub` / `mosquitto_sub`) and a reachable
  broker for `mqtt-context`, and for `todo-prefix`'s MQTT fallback — see
  [MQTT Integration](./mqtt-integration.md).
